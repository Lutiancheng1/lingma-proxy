# Lingma Feishu Agent vs 飞书 Aily — 功能场景对比

> 面向业务决策者和非技术用户。不讲技术细节，只讲「拿到手能干什么」。

---

## 一句话说清楚

飞书 Aily 是飞书官方的 AI 助手，能帮你查信息、整理文档、分析数据。

Lingma Feishu Agent 是我们自研的飞书 AI 员工，不仅能做 Aily 能做的所有事，还能直接帮你操作飞书（建文档、改权限、查日程、读表格），并且在长对话中不会忘记前面聊的内容。

---

## 场景一：查日程

**你要做的事**：看看今天有什么会，明天有什么安排。

| | 飞书 Aily | Lingma Feishu Agent |
|---|---|---|
| 能不能查 | 能，问它就行 | 能，问它就行 |
| 能不能建 | 不确定，依赖官方接口开放程度 | 能，直接帮你创建日程事件 |
| 多轮对话 | 问完就完了，下次重新问 | 记得你之前问过，还能接着聊 |

**实际效果**：你在飞书群里说「帮我看看明天有什么会」，Agent 直接列出明天的日程。你接着说「把下午 3 点那个会取消」，它帮你处理。你再说「帮我建一个后天上午 10 点的周会」，它直接创建。全程不用切到日历应用。

## 场景二：读文档、建文档

**你要做的事**：读一个长文档的核心内容，或者基于某个主题新建一份文档。

| | 飞书 Aily | Lingma Feishu Agent |
|---|---|---|
| 读文档 | 能，可以总结文档内容 | 能，长文档自动分块读取，不丢细节 |
| 建文档 | 不支持直接创建 | 能，直接在飞书云盘里创建新文档 |
| 改权限 | 不支持 | 能，帮你把文档设为「互联网所有人可阅读」 |

**实际效果**：你在群里说「帮我读一下这个文档，总结核心要点」，Agent 读完给你摘要。你说「把这个总结写成一份新文档」，它直接在飞书云盘里创建。你说「把这个文档的链接权限改成公开可读」，它帮你改好。

## 场景三：查表格、读数据

**你要做的事**：从一个电子表格或多维表格里查数据。

| | 飞书 Aily | Lingma Feishu Agent |
|---|---|---|
| 读表格 | 能，可以做数据分析和总结 | 能，支持分块读取大表格 |
| 多维表格 | 能，通过多维表格集成 | 能，直接读取多维表格记录 |
| 跨表查询 | 有限 | 能，可以同时查多个表格 |

**实际效果**：你说「帮我看看 Q2 销售表里华南区的数据」，Agent 读取表格并给你汇总。你说「跟 Q1 对比一下增长了多少」，它继续查 Q1 表格做对比分析。

## 场景六：长对话、多轮协作

**你要做的事**：跟 AI 连续聊 20 分钟以上，讨论一个复杂问题。

| | 飞书 Aily | Lingma Feishu Agent |
|---|---|---|
| 上下文长度 | 有限，长了会忘前面的 | 四级水位线自动管理，关键信息不丢 |
| 记忆系统 | 有基础记忆 | 工具记忆全文搜索 + 飞书历史搜索 |
| 压缩策略 | 简单截断 | 结构化压缩，保留决策和待办 |

**实际效果**：你跟 Agent 聊了 30 分钟，讨论了一个产品方案。中间它帮你查了日程、读了文档、搜了表格。到第 25 分钟时，你说「回到刚才那个文档的第三点」，它还记得是哪个文档、第三点是什么。如果上下文满了，它会自动压缩前面的对话，但保留你做过的决策和待办事项。

## 场景七：定时任务

**你要做的事**：让 AI 每天早上 9 点自动发一份日报，或者 5 分钟后提醒你做某件事。

| | 飞书 Aily | Lingma Feishu Agent |
|---|---|---|
| 定时执行 | 支持主动监听和触发 | 支持 cron 循环和一次性延迟 |
| 管理任务 | 通过 Aily 配置 | 群聊里直接 /schedule 管理 |
| 静默模式 | 不确定 | 支持，执行完不发消息 |

**实际效果**：你说「帮我设一个每天早上 9 点的任务，查看今天的日程并发到这个群里」，Agent 创建定时任务，每天自动执行。你说「5 分钟后提醒我开会」，它设一个一次性提醒。

---

## 场景八：工具扩展

**你要做的事**：让 AI 能调用更多外部工具。

| | 飞书 Aily | Lingma Feishu Agent |
|---|---|---|
| 内置工具 | 飞书官方集成 | 30+ 结构化工具 |
| 外部扩展 | 通过妙搭平台 | MCP 协议，连接任意外部工具 |
| 自定义 | 通过 Aily 平台配置 | MCP 服务器配置，或自定义 Skill |

**实际效果**：Agent 通过 MCP 协议可以连接你公司的内部系统、外部 API、数据库等任何工具。不需要在飞书平台上重新开发，配置一个 MCP 服务器就行。

---

## 场景九：安全控制

**你要做的事**：确保 AI 不会乱改文件、乱发消息。

| | 飞书 Aily | Lingma Feishu Agent |
|---|---|---|
| 文件访问 | 飞书权限体系 | 白名单 + 确认覆盖/删除保护 |
| 操作确认 | 平台级权限 | 敏感操作需要用户明确确认 |
| 授权流程 | 飞书 OAuth | 设备流登录，Agent 不能直接操作凭证 |

**实际效果**：Agent 默认只能读写你授权的目录。要删除文件时，它会要求你明确说「确认删除 xxx」。要覆盖已有文件时，需要你说「确认覆盖 xxx」。它不能自己执行登录操作，遇到权限不够时会给你一个授权链接。

---

## 场景十：错误恢复

**你要做的事**：AI 执行某个操作失败了，希望它能自己修好。

| | 飞书 Aily | Lingma Feishu Agent |
|---|---|---|
| 参数错误 | 报错 | 自动查阅文档重试 |
| 权限错误 | 报错 | 自动发起授权流程 |
| 连续失败 | 报错 | 分析根因，向用户报告阻塞原因 |

**实际效果**：Agent 帮你查日程时参数不对，它不会直接报错给你，而是自己去查正确的参数格式，然后重试。权限不够时，它会给你一个授权链接，你点一下授权就行。

## 我们的优势在哪

1. **操作能力更强**：Aily 主要是「查」和「分析」，我们能「查」+「分析」+「操作」。建文档、改权限、发消息、读表格，这些 Aily 做不到或者做得不好的，我们都能做。

2. **长对话不丢信息**：Aily 的上下文管理比较简单，聊长了会忘。我们有四级水位线 + 工具记忆全文搜索 + 飞书历史搜索，30 分钟以上的对话也能记住关键决策和待办。

3. **工具可扩展**：Aily 的工具扩展依赖飞书妙搭平台。我们通过 MCP 协议可以连接任何外部系统，不需要在飞书平台上重新开发。

4. **自主错误恢复**：Aily 遇到错误就报错。我们的 Agent 会自己分析错误、查文档重试、权限不够自动发起授权。

5. **本地部署**：Aily 是飞书云端服务。我们跑在本地桌面，数据不出本机，适合对数据安全有要求的场景。

---

## 适合什么场景用

- **日常办公**：查日程、读文档、搜文件、发消息 — 两个都能用，我们操作能力更强
- **数据分析**：读表格、多维表格、跨表查询 — 两个都能用，我们支持大表格分块
- **长对话协作**：讨论方案、做决策、连续操作 — 我们明显更强，不丢上下文
- **自动化任务**：定时日报、自动提醒、定期检查 — 我们支持 cron 和一次性延迟
- **系统集成**：连接内部系统、外部 API — 我们通过 MCP 协议，Aily 通过妙搭
- **数据安全**：敏感数据不能上云 — 我们本地部署，Aily 是云端服务
